# AI Gateway 2.0 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a parallel AI Gateway 2.0 track (`kong-2.0/`, `docs-2.0/`) to `kong-claude-ai-gateway`, mirroring modules 0-7 of the existing `decK`/AI-GW-1.x track, using `kongctl` against a real Konnect org, with every module's status live-verified rather than assumed.

**Architecture:** Same shape as the existing repo — one cumulative `kongctl` YAML per module in `kong-2.0/`, one walkthrough doc per module in `docs-2.0/`, a `docker-compose.aigw2.yml` overlay running the `kong/kong-ai-gateway-dev` hybrid data plane, and a `scripts/verify-2.0.sh` mirroring `scripts/verify.sh`'s per-module case-statement pattern. Live verification happens against the Fel Tech org via `KONNECT_TECH_TOKEN` (already present in `~/.kong-se/secrets.env`) during implementation; the shipped repo's `.env.2.0.example` uses generic variable names so any reader can point it at their own org.

**Tech Stack:** `kongctl` (>=1.6.0, already installed), Docker Compose, `kong/kong-ai-gateway-dev` image, `curl`/`jq` for verification, bash for scripts.

## Global Constraints

- Every module's status banner must reflect a result actually observed against a real Konnect org during this implementation — never transcribed from `aigw2.0-test/AIGW-2.0-CRITERIA-PROGRESS.md` without a fresh live check. That scoreboard is prior-art context only (cite it when it matches or diverges), per the approved design spec.
- Module 1 must test **both** a direct Anthropic API key target and a Bedrock-backed target, Anthropic-direct as primary (per the design spec).
- Auth (`openid-connect`) attaches via `model.access.identity_providers`, never `policies:` — putting it under `policies:` silently drops the whole config to 0 routes while the CP still reports success. Every module 3+ task must use `identity_providers`.
- Use `model_providers:` as the resource key, not the legacy `providers:` (kongctl dropped the old key — see `ai-gateway-test-harness/SE-FINDINGS-AND-BEST-PRACTICES.md` A6).
- Vault refs use `{vault://<vault-ref>/<key>}`, resolved via a `ai_gateway_vault` (`type: konnect`) resource — never inline a credential in a committed YAML file.
- After every `kongctl apply`, confirm the DP's compiled config actually shows the expected route/plugin chain via `GET :8001/config` before treating a module as verified — the CP can report success while the DP silently drops routes (shakeout finding, `SE-FINDINGS-AND-BEST-PRACTICES.md` A2/A4).
- Module 6 has no `kong-2.0/*.yaml` (Admin-API-only, same reason as the 1.x module 6). Module 8 is out of scope (still "planned" in 1.x too).

echo "    3. Copy the control plane's cluster endpoint / telemetry endpoint"
echo "       (same screen as step 1) into .env.2.0 as"
echo "       KONNECT_AIGW2_CP_ENDPOINT / KONNECT_AIGW2_TELEMETRY_ENDPOINT"

```yaml
_defaults:
  kongctl:
    namespace: kong-claude-ai-gateway-2.0

ai_gateways:
- ref: claude-ai-gateway
  _external:
    selector:
      matchFields:
        name: "claude-ai-gateway"

  model_providers:
  - ref: anthropic-direct
    name: anthropic-direct
    display_name: "Anthropic (direct key)"
    type: anthropic
    config:
      auth:
        type: basic
        headers:
        - name: x-api-key
          value: "{vault://ai-vault/anthropic-api-key}"

  - ref: bedrock-claude
    name: bedrock-claude
    display_name: "AWS Bedrock (Claude)"
    type: bedrock
    config:
      auth:
        type: aws
        aws_access_key_id: "{vault://ai-vault/aws-access-key-id}"
        aws_secret_access_key: "{vault://ai-vault/aws-secret-access-key}"
        aws_region: "{vault://ai-vault/aws-region}"

  models:
  - ref: claude-chat
    type: model
    name: claude-chat
    display_name: "Claude Chat"
    enabled: true
    config:
      route:
        paths:
        - /anthropic
      model:
        alias: "@claude/chat"
    formats:
    - type: anthropic
    target_models:
    - name: claude-sonnet-4-6
      provider: anthropic-direct
      weight: 100
      config:
        type: anthropic
        upstream_url: https://api.anthropic.com/v1/messages
        anthropic_version: "2023-06-01"
    - name: claude-bedrock-alt
      provider: bedrock-claude
      weight: 0
      config:
        type: bedrock
        bedrock_model_id: us.anthropic.claude-sonnet-4-5-20250929-v1:0
    capabilities:
    - generate
```

Note: `weight: 0` on the Bedrock target keeps it registered but out of the

#!/usr/bin/env bash
# Module 6 (AI Gateway 2.0): pushes a Konnect Advanced Analytics dashboard

  definition: {
    tiles: .tiles,

}' observability/claude-code-usage-dashboard.json)

  | jq -r '.data[0].id // empty')

else

  curl -sf "${auth[@]}" -X POST "${API}/v2/dashboards" --data "$dashboard_payload" > /dev/null
fi

echo "==> Done. Konnect UI -> Analytics -> Dashboards -> Claude AI Gateway 2.0 Usage"
